## Pattern Overview

**Overall:** Single-page application (SPA) with **tab-state routing** — no React Router, no URL-based navigation, no server API layer.

**Key Characteristics:**
- All application state lives in `App.tsx` and is passed down as props (container/presentational split).
- Views are switched by `currentTab: NavTab` (`'list' | 'map' | 'post' | 'setting' | 'detail'`).
- Persistence is client-only via `localStorage` with lazy initialization from mock seeds.
- Styling is inline Tailwind utility classes matching the Google Stitch "Structured Minimalist" / Notion-adjacent aesthetic.
- Interactions (claim, post, chat) use `setTimeout` to simulate async behavior — no network calls.

## Layers

**Presentation (View components):**
- Purpose: Render UI screens; receive data and callbacks via props; hold only local UI state (drawer expanded, claiming spinner, form fields).
- Location: `src/components/*.tsx`
- Contains: React FC components with Tailwind classes, Material Symbols icons
- Depends on: `src/types.ts`
- Used by: `src/App.tsx`

**Application / State (App container):**
- Purpose: Tab navigation, business handlers, persistence, cross-view coordination
- Location: `src/App.tsx`
- Contains: `useState` for items/zones/settings/messages/tabs; `useEffect` for localStorage sync; handler functions
- Depends on: components, types, `src/data/initialItems.ts`
- Used by: `src/main.tsx` entry

**Domain model:**
- Purpose: TypeScript contracts for items, zones, settings, chat
- Location: `src/types.ts`
- Contains: `Item`, `Zone`, `Owner`, `AppSettings`, `ChatMessage`, `NavTab`, `Category`
- Depends on: nothing
- Used by: App and all components

**Data seed (mock repository):**
- Purpose: Static demo inventory and alert zones
- Location: `src/data/initialItems.ts`
- Contains: `INITIAL_ITEMS` (11 items), `INITIAL_ZONES` (2 zones) — mixed global cities plus some Venice entries
- Depends on: `src/types.ts`
- Used by: `App.tsx` (fallback when localStorage empty)

**Design reference (non-runtime):**
- Purpose: Canonical UI spec and static HTML prototypes
- Location: `.planning/google-stitch-ui-design/`
- Contains: `DESIGN.md` (tokens, typography, components), five `*_notion_style/code.html` screens
- Depends on: nothing at runtime
- Used by: human/planner reference; informed AI Studio generation

**Build / bootstrap:**
- Purpose: Vite dev server, React mount, global CSS
- Location: `index.html`, `src/main.tsx`, `vite.config.ts`, `src/index.css`
- Contains: Inter + Material Symbols font loading, Tailwind v4 `@import`, path alias `@/*`

## Data Flow

### Primary navigation path

1. User taps bottom nav tab → `BottomNav.onTabChange` → `App.setCurrentTab` (`src/App.tsx:286-292`)
2. `App` conditionally renders the matching view component (`src/App.tsx:226-272`)
3. View receives filtered data and handler props from App state

### Item selection → detail flow

1. User clicks item card in `ListView` or `MapView` → `onSelectItem(item)` (`src/App.tsx:103-107`)
2. App sets `selectedItem` and `currentTab = 'detail'`
3. `ItemDetailView` renders with claim/message handlers wired back to App

### UGC post flow

1. User submits form in `PostItemView` → builds `Item` object client-side (`src/components/PostItemView.tsx:56-93`)
2. `onPostSuccess(newItem)` → App prepends to `items`, navigates to detail (`src/App.tsx:118-122`)
3. `useEffect` persists updated items to `localStorage` (`src/App.tsx:86-88`)

### Claim flow

1. User clicks Claim in list or detail → local loading state → `onClaimItem(id)` after 600ms timeout
2. App maps over `items`, sets `isAvailable: false, claimedBy: 'me'` (`src/App.tsx:109-116`)
3. Persisted to localStorage on next render cycle

### Chat / message flow (UGC prototype)

1. Detail view "Message Owner" → `setChatItem` opens `ChatModal` (`src/App.tsx:267-270`)
2. User sends message → `handleSendMessage` appends to `messages[itemId]` (`src/App.tsx:172-184`)
3. Simulated owner reply via `setTimeout` 1200ms (`src/App.tsx:187-202`)

### Persistence hydration

1. On mount, each state slice reads `localStorage` key or falls back to seed/mock (`src/App.tsx:22-83`)
2. On every state change, corresponding `useEffect` writes JSON back (`src/App.tsx:86-100`)

**State Management:**
- React `useState` at App root only — no Context, Redux, Zustand, or React Query
- No derived-state memoization (`useMemo`/`useCallback` not used)
- Language setting affects `BottomNav` labels only; view copy remains English

## Key Abstractions

**`Item` (listing):**
- Purpose: Unified shape for scraped and UGC listings in the draft (no `source` discriminator yet)
- Examples: `src/types.ts:16-39`, instances in `src/data/initialItems.ts`
- Pattern: Flat interface with nested `owner: Owner`; geo via `lat`/`lng`; availability via `isAvailable`

**`NavTab` (view router):**
- Purpose: String union driving which screen renders
- Examples: `src/types.ts:1`, usage throughout `src/App.tsx`
- Pattern: `'detail'` is a pseudo-route overlay — bottom nav treats detail as list-active (`src/components/BottomNav.tsx:30`)

**`Zone` (alert geography):**
- Purpose: User-defined monitoring areas for push notifications (UI only)
- Examples: `src/types.ts:41-48`, `INITIAL_ZONES` in `src/data/initialItems.ts`
- Pattern: CRUD in Settings; status toggle ACTIVE/PAUSED

**localStorage keys (client DB):**
- Purpose: Simulate server persistence for demo/prototype sessions
- Keys: `shoumanwu_items`, `shoumanwu_zones`, `shoumanwu_settings`, `shoumanwu_messages`
- Pattern: JSON serialize/deserialize with try/catch fallback to seeds

## Architectural Constraints

- **Threading:** Single-threaded browser event loop; simulated delays via `setTimeout` only
- **Global state:** All mutable app state in `App.tsx` — components are stateless except local UI toggles
- **Circular imports:** None detected; flat import graph: components → types, App → components + data
- **No routing:** Deep links, browser back/forward, and share URLs do not map to views (Header share uses `window.location.href` as-is)
- **No auth:** Profile modal shows hardcoded email; no OAuth/session gates despite `metadata.json` geolocation permission request
- **No real map:** `MapView` places pins by index-derived percentages, not `Item.lat`/`Item.lng` (`src/components/MapView.tsx:113-115`)
- **Geographic inconsistency:** Mock data spans Shanghai, Berlin, Tokyo, Venice; `PostItemView` defaults to Shanghai; `MapView` zone chips include Venice + Jing'an — product target is Venice per `.planning/PROJECT.md`
- **Declared but unused deps:** `@google/genai`, `express`, `dotenv` in `package.json` — no `server.js` or API routes exist; `GEMINI_API_KEY` in `.env.example` is AI Studio boilerplate

## Anti-Patterns

### Tab state instead of URL routing

**What happens:** Navigation is `useState<NavTab>` with no sync to URL hash or path.
**Why it's wrong:** Breaks shareable item links, PWA install deep links, and browser history — all required for a map-first discovery PWA.
**Do this instead:** Adopt file-based or declarative routing (planned: Next.js App Router per `.planning/research/ARCHITECTURE.md`) with routes like `/[locale]/listing/[id]`.

### Monolithic App container

**What happens:** `App.tsx` holds ~300 lines of state, handlers, and view switching.
**Why it's wrong:** Will not scale when API hooks, auth gates, scraped vs UGC branching, and i18n are added.
**Do this instead:** Extract hooks (`useItems`, `useSettings`), a thin router layout, and data-fetch layers before wiring Supabase/API.

### Hardcoded design tokens in components

**What happens:** Components use inline hex (`#37352f`, `#df6b05`) despite `@theme` tokens in `src/index.css`.
**Why it's wrong:** Drift from Stitch `DESIGN.md` and harder Phase 2 theming/dark mode.
**Do this instead:** Use Tailwind semantic classes mapped to `@theme` variables (e.g., `bg-surface`, `text-on-surface`, `text-accent-orange`).

### Mock geo on map

**What happens:** Pin positions ignore real coordinates.
**Why it's wrong:** Core product value is GPS-accurate Venice discovery; current map misleads UX testing.
**Do this instead:** Integrate MapLibre GL JS with `Item.lat`/`lng` and zone polygons per research architecture.

## Error Handling

**Strategy:** Minimal — try/catch on JSON parse for localStorage hydration; `console.error` on failure; fall back to seed data.

**Patterns:**
- localStorage read failures silently revert to `INITIAL_ITEMS` / defaults (`src/App.tsx:24-31`)
- Form validation uses `alert()` for missing title (`src/components/PostItemView.tsx:43-45`)
- Share API failure caught with empty handler (`src/components/Header.tsx:64`)
- No error boundaries, no toast system, no network error handling (no network layer)

## Cross-Cutting Concerns

**Logging:** `console.error` only on localStorage parse failures; no structured logging

**Validation:** Client-side only — required title on post form; no schema validation library (zod etc.)

**Authentication:** Not implemented; settings profile is a static modal stub (`src/components/SettingsView.tsx:268-296`)

**i18n:** Partial — `AppSettings.language` drives bottom nav labels (`src/components/BottomNav.tsx:11-18`); all other UI strings are hardcoded English (plus Chinese app title 手慢无). Planned: Italian primary, en/zh per `.planning/PROJECT.md`

**PWA:** `metadata.json` declares geolocation and Gemini server capability (AI Studio artifact); no `manifest.json` or service worker in repo root
