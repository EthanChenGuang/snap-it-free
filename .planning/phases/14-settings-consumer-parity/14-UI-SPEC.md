> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

## Design System

| Property | Value |
|----------|-------|
| Tool | none — shadcn is not used in this project |
| Preset | not applicable |
| Component library | none (custom components; a few headless Radix primitives used elsewhere in the app, unrelated to this phase) |
| Icon library | Material Symbols Outlined (`FILL 0, wght 400, GRAD 0, opsz 24`), loaded in `app/layout.tsx` |
| Font | Inter, loaded via `next/font/google` in `app/layout.tsx` |

**Why no shadcn gate:** `components.json` does not exist (confirmed by directory scan) and the project is **not** shadcn-based. The whole app is governed by a locked, pre-existing custom design system — **Google Stitch "Structured Minimalist"** — enforced project-wide by `.planning/google-stitch-ui-design/SKILL.md` and `.planning/google-stitch-ui-design/DESIGN.md`. Tokens are already implemented as Tailwind v4 `@theme` CSS variables in `app/globals.css`. This UI-SPEC extends that existing system for the two net-new Phase 14 surfaces only — it does not introduce a new design language.

**Scope note (per CONTEXT.md scouting finding):** Most of the settings screen is already built and already Stitch-aligned — `GeneralSection`, the existing rows of `NotificationsSection` (push toggle, sound toggle), `ZonesSection`, `LanguageSection`, and `AdvancedSection` are unchanged this phase and are **not** re-specified below. This contract covers only the two net-new surfaces:

1. **DND (quiet hours) toggle + time-picker rows** — nested inside `NotificationsSection`, shown only when Push Notifications is on (D-06).
2. **New "Account" danger-zone section** — Delete Account row with two-step inline confirm + conditional active-claims warning line (D-12, D-13, D-17), positioned right after General.

**Screen prototype reference (mandatory reading before implementation, per project skill):**
- `.planning/google-stitch-ui-design/setting_notion_style/screen.png` + `code.html` — reference mockup for General/Profile, Push+Sound toggles, Zones cards, Language pills, red-bordered Advanced danger box. **Note (repeated from CONTEXT.md — do not treat as literal spec):** this mockup predates DND and Delete Account as concepts in this app — it has **no DND row and no Delete Account row**. Both net-new surfaces below are **extensions from DESIGN.md tokens**, styled to match the mockup's existing card/toggle/danger-box idioms, not copied verbatim from any single element in it.
- `components/settings/NotificationsSection.tsx` — existing push/sound toggle rows; DND nests as additional rows inside the same `SettingsCard`
- `components/settings/AdvancedSection.tsx` — existing two-step inline destructive-confirm pattern (`confirming` state + `onBlur` reset) — the exact interaction model to replicate for Delete Account (D-12)

**Primary visual focal point:** Neither net-new surface should visually dominate the settings screen — this is a form/preferences page where every row should read as an equally-weighted list item, consistent with the existing screen's flat-card rhythm. The Account section is the one place where a deliberate danger-box color departure (red-tinted border/background, matching `AdvancedSection`'s existing `border-error/20 bg-error-container/30` treatment) is intentional and documented — not a new pattern being invented here.

## Spacing Scale

Project uses the Stitch 4px-grid scale (5 tokens — this is the existing project convention, already used throughout `NotificationsSection`/`AdvancedSection`/`GeneralSection`):

| Token | Value | Usage in this phase |
|-------|-------|----------------------|
| `space-xs` | 4px | Gap between DND label and its helper/error text; gap between time-input hour/minute segments |
| `space-sm` | 8px | Gap between the two time inputs in the start/end row; gap between Account section title and card |
| `space-md` | 16px | Row internal padding (`p-space-md`), matching every existing `SettingsCard` row; gap between stacked rows within the DND sub-block |
| `space-lg` | 24px | Section-to-section vertical gap (`mb-space-xl` uses 48px — see below; `space-lg` used for the Account card's internal padding, matching `AdvancedSection`'s `p-space-md`→pattern is actually `p-space-md`, so keep consistent — see Component Inventory) |
| `space-xl` | 48px | Section bottom margin (`mb-space-xl`), matching every existing `<section>` wrapper in `SettingsPageClient` |

Exceptions:
- Touch targets: the two DND time `<input type="time">` elements and the Delete Account button use `min-h-11` (44px) even though the visual row height (with `p-space-md` = 16px vertical padding) is close to but not guaranteed to hit 44px on all font-rendering — this is a documented minimum-touch-target exception, not a violation of the 4px grid (the grid governs spacing between elements, not the accessibility floor for tap targets).
- The DND on/off toggle itself reuses `SettingsToggle` verbatim (already `h-5 w-10` track, `after:h-4 after:w-4` thumb) — no new toggle component or size is introduced.

## Typography

Declared for the two net-new surfaces only (existing screen typography — `body-md`, `label-sm`, `label-md` — is unchanged elsewhere and out of scope):

| Role | Size | Weight | Line Height | Used for |
|------|------|--------|-------------|----------|
| Body | 15px (`body-md`, project token — token weight is 400 already, no override needed) | 400 | 1.6 | DND row primary label ("Do Not Disturb"), Delete Account row primary label ("Delete account") — matches every existing `SettingsCard` row primary line (`text-body-md font-medium text-on-surface` pattern used in `NotificationsSection`/`GeneralSection`) |
| Label | 12px (`label-sm`, project token — token weight is 500 by default) | **400 — explicit override, not the bare token** | 1.2 | DND helper/description text, DND time-input labels ("Start" / "End"), active-claims warning line, Delete Account helper/description text — matches the existing `text-label-sm text-secondary` pattern already used for every row's helper line in `NotificationsSection`/`AdvancedSection` (those existing usages already carry the same override — this is not a new pattern, just confirming it applies here too) |
| Label (emphasis) | 12px (`label-sm`) | **600 — explicit `font-semibold`, matches the danger-box heading weight already used in `AdvancedSection`'s `text-body-md font-bold text-error` for its title** | 1.2 | Delete Account button label in both states ("Delete account" / "Tap again to confirm") — reuses `AdvancedSection`'s exact button text treatment (`text-label-md`, not `label-sm` — see correction below) |
| Heading (section title) | 14px (`label-md`, project token, uppercase, tracking-wider) | **500 — bare token, unchanged** | 1.4 | New "Account" `SettingsSectionTitle` — reuses `SettingsSectionTitle` component verbatim, no override needed since that component is unchanged by this phase |

**Correction — Delete Account button label uses `label-md` not `label-sm`, matching `AdvancedSection` exactly:** `AdvancedSection`'s existing reset button renders `text-label-md text-error` (14px, project token weight 500). To keep the two-step-confirm pattern visually identical per D-12 ("matching the existing AdvancedSection pattern exactly"), the Delete Account button must reuse the same `text-label-md` class, **not** introduce a new `label-sm` size for it. This supersedes the "Label (emphasis) 12px" row above for the button specifically — the button is 14px/500 (bare `label-md` token, no override), consistent with `AdvancedSection`. The two-weight budget below reflects the corrected reality.

**Weight contract:** exactly **2 weights** across these two net-new surfaces — **400 regular** (row primary labels via `font-medium`... — see note below on `font-medium` vs `font-normal`) and **500 medium** (bare `label-sm`/`label-md` tokens where used without override, e.g. the button label and section title) — plus the explicit **400 override** applied to helper/description text where the bare `label-sm` token would otherwise render 500. This mirrors the exact same weight budget already in use by `NotificationsSection`/`AdvancedSection` today (`font-medium` primary rows, unstyled-token helper rows) — **no new weight is introduced by this phase.**

*(Clarification: the existing codebase's `font-medium` utility on `text-body-md` rows is a Tailwind class, distinct from the Stitch token's own default weight — `body-md` token weight is already 400, and `font-medium` bumps it to 500 for row primary labels. So the two effective weights rendered are 400 (helper/description text, explicit `label-sm` override where needed) and 500 (row primary labels via `font-medium`, and bare `label-md`/`label-sm` tokens for the section title and button). This is the same two-weight budget the rest of the settings screen already uses — verify against `GeneralSection`/`NotificationsSection` before implementing, do not invent a third weight.)*

## Color

Monochrome-first system (DESIGN.md). Net-new surfaces' color usage:

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#f9f9f8` (`bg-surface` / `bg-background`) | Page background (unchanged, inherited) |
| Secondary (30%) | `#ffffff` (`surface-container-lowest`) — `SettingsCard` background for both the DND sub-block and the Account card; `#f4f4f3` (`surface-container-low`) — optional hover tint if Delete Account row becomes a button-row (not required, `AdvancedSection`'s button doesn't use row hover) | Cards, row backgrounds |
| Accent (10%) | `#000000` (`primary`) | **Reserved exclusively for:** the DND on/off toggle's checked-state fill (`peer-checked:bg-primary`, inherited unchanged from `SettingsToggle`). Not used anywhere else on these two surfaces — time inputs, labels, and the Account section use no accent color at all. |
| Destructive | `#ba1a1a` (`error`) / `error-container` `#ffdad6` (used at low opacity per existing pattern) | **Reserved exclusively for:** the Account section's danger-box treatment (border + tinted background + heading + button, all `error`-token-based, replicating `AdvancedSection`'s exact `border-error/20 bg-error-container/30 text-error` combination) and the active-claims warning line text (D-17) |

Accent reserved for: the DND toggle's on-state fill only. No other new element on these two surfaces uses the black accent — this keeps the danger-zone visually distinct (red-only) from the notification toggle (black-only), avoiding any competing accent signal on the same screen.

**Documented Stitch pattern reuse (not a new exception):** the Account section's red-tinted danger box is not a new color decision — it is the exact `border-error/20 bg-error-container/30` combination already established by `AdvancedSection` for "Advanced" (Reset Cache & Data). Applying the identical treatment to "Account" (Delete Account) keeps both destructive sections visually consistent with each other, per D-13's explicit framing of Account as a second "danger-zone section."

New keys route under `messages.settings.dnd.*` (nested inside the existing `settings.push`/`settings.sound` sibling pattern) and `messages.settings.account.*` (new top-level settings sub-object, sibling to `settings.advanced`).

|---------|------|
| Primary CTA (Delete Account button, idle state) | **"Delete account"** — `settings.account.deleteButton` |
| Primary CTA (Delete Account button, confirm state) | **"Tap again to confirm"** — `settings.account.confirmDelete` (matches `AdvancedSection`'s exact "tap again to confirm" phrasing pattern — reuse the same construction, not `settings.advanced.confirmReset`'s literal "Confirm reset" wording, since D-12 requires the *interaction pattern*, and this label should read naturally for the higher-stakes action) |
| DND section label | **"Do Not Disturb"** — `settings.dnd.title` |

| DND toggle aria-labels | **"Do Not Disturb on"** / **"Do Not Disturb off"** — `settings.dnd.enabledLabel` / `settings.dnd.disabledLabel` (mirrors `settings.push.enabledLabel`/`disabledLabel` construction) |
| Empty state | Not applicable — neither net-new surface is a list/collection. DND always renders its toggle (with times hidden/shown per D-08's three-state model); Account always renders its one row. |
| Error state — DND save fails | **"Could not save quiet hours — try again"** — `settings.dnd.saveError` (mirrors `settings.push.subscribeError`'s "Could not enable push notifications — try again" construction) — 🧪 backstop, needs explicit test that a failed PATCH surfaces this inline, matching `NotificationsSection`'s existing `error` state pattern (`<p className="text-label-sm text-error">`) |

| Destructive confirmation | **Delete account: two-step inline tap-to-confirm** (D-12) — first tap changes button label from `settings.account.deleteButton` ("Delete account") to `settings.account.confirmDelete` ("Tap again to confirm"); second tap within the same session triggers the delete API call; `onBlur` resets to idle state (identical mechanics to `AdvancedSection.handleReset`) |

## UI Considerations

> Populated by the ui-phase UI-consideration probe (Step 9.5) and lifted by plan-phase's
> `## UI Considerations` lift rule via the identical rule as SPEC `## Edge Coverage`. Shape-rooted UI *state*
> coverage (empty / loading / error / populated / partial / overflow / zero-one-many / long-text).
> Empty-state and error-state COPY live in `## Copywriting Contract` above — this section covers
> state coverage and REFERENCES those rows rather than restating the copy (de-dup).

**Elements classified for this phase:**
- DND on/off toggle (`interactive-control`)
- DND start/end time inputs (`interactive-control`, `form`)
- Delete Account two-step confirm button (`interactive-control`, `form`)
- Active-claims warning line (`static-content`, conditional)

Applicable state considerations resolved: 7 covered, 2 backstop, 1 unresolved

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| loading | DND toggle + time inputs | ✅ covered | On mount, `NotificationsSection` fetches saved quiet-hours prefs (mirrors the existing `refreshSubscription`/`ZonesSection` fetch pattern); render toggle in its default `off` state with times hidden until the fetch resolves — no separate skeleton needed since the row already exists structurally, only its checked-state and time values are async |
| populated (three-state) | DND toggle + time inputs | ✅ covered | D-08's three states are explicit: (1) off — toggle unchecked, time inputs hidden entirely (not just disabled — hidden, per D-06's "shown only when Push Notifications is on" framing extended to the DND sub-toggle itself for visual cleanliness); (2) configured-but-paused — toggle unchecked but a saved start/end exists in state, so re-enabling doesn't require re-entry; (3) active — toggle checked, time inputs visible and editable |
| partial | DND time inputs | ✅ covered | D-05/D-07: each `<input type="time">` auto-saves independently on change (PATCH immediately per D-07) — a user can set only Start and leave End at its default without any blocking validation; no "both required before save" gate exists per CONTEXT.md's decisions |
| error | DND save (PATCH failure) | 🧪 backstop | `settings.dnd.saveError` copy defined above; needs explicit test that a failed PATCH request surfaces the inline error text without silently reverting the toggle/time UI state |
| error | Delete Account request failure | 🧪 backstop | `settings.account.deleteError` copy defined above; needs explicit test that a failed delete API call resets the two-step confirm state to idle (not stuck on "tap again to confirm") and surfaces the error inline |
| zero-one-many | Active-claims warning line | ✅ covered | Explicit singular/plural copy variants defined in Copywriting Contract (`n === 1` vs `n > 1`); `n === 0` renders no warning line at all (D-17 only triggers the line when claims exist) |
| overflow / long-text | DND helper text, Account danger-box description | ✅ covered | All copy is short, fixed-vocabulary, non-user-generated (translator-authored strings only) — no truncation/wrap handling needed, consistent with every other settings row on this screen |
| empty | DND / Account sections | not applicable | Neither surface is a list/collection — DND always shows its toggle, Account always shows its one row; there is no "zero items" state to design |
| conditional visibility (DND gating) | DND sub-block within `NotificationsSection` | ⚠ unresolved | D-06 locks "shown only when Push Notifications is on" but CONTEXT.md doesn't specify the exact behavior when a user turns Push OFF while DND was previously configured ON — does the DND sub-block simply hide (preserving its saved state for when Push is re-enabled, consistent with D-08's "configured-but-paused" philosophy) or does turning Push off also force-disable DND server-side? Recommend: **hide only, do not force-disable** — the quiet-hours row is enforcement-scoped to "all server push" per D-04, and if Push itself is off there's nothing to suppress, so no forced write is needed; this is a planner decision to confirm, not locked here |

## Component Inventory (this phase)

Reused verbatim (no visual change):
- `components/settings/SettingsUi.tsx` — `SettingsToggle` (DND on/off toggle), `SettingsCard` (both the DND sub-block wrapper and the new Account card), `SettingsSectionTitle` (new "Account" heading)

Modified this phase:
- `components/settings/NotificationsSection.tsx` — add DND sub-block (toggle row + conditional start/end time-input row) inside the existing `SettingsCard`, below the Sound Alerts row, gated on `pushEnabled` (D-06); follows the same `flex items-center justify-between gap-space-md p-space-md` row shape and `border-b border-outline-variant` divider pattern already used between the Push and Sound rows
- `components/settings/SettingsPageClient.tsx` — insert new `<AccountSection />` between `<GeneralSection />` and `<NotificationsSection />`... **correction: per D-13's locked order (General → Notifications → Zones → Language → Account → Advanced), `AccountSection` goes between `<LanguageSection />` and `<AdvancedSection />`, not right after `GeneralSection`.** ⚠ **Spec conflict flagged for planner:** CONTEXT.md's prose in the `<decisions>` block states D-13 twice with different orderings — the D-13 bullet says "positioned right after General, ahead of Zones/Language" but the same bullet's "Full section order" sentence says "General → Notifications (with nested DND) → Zones → Language → Account (danger zone) → Advanced" (Account last-but-one, not second). **This UI-SPEC follows the explicit "Full section order" sentence** (Account is 5th, right before Advanced) since it is the more complete, unambiguous statement and matches the phase brief's `<critical_context>` restatement verbatim. Planner must confirm this resolution before implementation — do not implement "right after General" without re-confirming with the user, since that reading would visually front-load a danger zone above every day-to-day settings section, which conflicts with the qualitative framing of Account being a low-frequency, deliberately de-prioritized action.

Net-new:
- `components/settings/AccountSection.tsx` — new component: `SettingsSectionTitle` + one `SettingsCard` styled identically to `AdvancedSection`'s danger-box treatment (`border-error/20 bg-error-container/30`), containing: heading (`settings.account.deleteTitle`), description (`settings.account.deleteDescription`), conditional active-claims warning line (D-17, only when `n > 0`), and the two-step confirm Delete Account button (`text-label-md`, `border-error`/`bg-error` hover states, matching `AdvancedSection`'s button class list exactly)
- Time-input sub-markup inside `NotificationsSection.tsx` — two native `<input type="time">` elements (Start/End), each wrapped with its `settings.dnd.startLabel`/`endLabel` text, laid out in a `flex items-center gap-space-sm` row; visible only when the DND toggle is checked (D-08's "active" state)
