## Design System

| Property | Value |

This UI-SPEC extends that existing system for Phase 13 screens only — it does not introduce a new design language.

## Spacing Scale

Project uses the Stitch 4px-grid scale (5 tokens, not the GSD default 7-token scale — this is the existing project convention, already used throughout `SelectLocationClient`/`SelectLocationMapPane`/`PostForm`):

| Token | Value | Usage in this phase |
|-------|-------|----------------------|
| `space-xs` | 4px | Icon-to-text gaps inside preview row, radius chip internal padding-y |
| `space-sm` | 8px | Radius chip group internal gap, confirm-panel internal row gaps |
| `space-md` | 16px | Confirm-panel padding, preview-row padding, PostForm location-row padding |
| `space-lg` | 24px | Screen gutter (`px-gutter`), header horizontal padding |
| `space-xl` | 48px | Not used on this screen (reserved for larger section breaks elsewhere in the app) |

Exceptions:
- Touch targets: locate-me FAB is 48×48px (`h-12 w-12`); header back button and confirm button use `min-h-11` (44px) — both exceed the 4px-grid literal value to satisfy the 44px minimum touch-target rule. Keep these as documented exceptions, not violations.
- Safe-area insets: locate-me FAB and bottom confirm panel add `env(safe-area-inset-bottom)` on top of the grid value — required for iOS PWA full-viewport screens (D-46).

## Typography

Phase 13 screens use a subset of the project's full Stitch type scale (see DESIGN.md for the complete scale). Declared for this phase:

| Role | Size | Weight | Line Height | Used for |
|------|------|--------|-------------|----------|
| Body | 15px (`body-md`) | 400 | 1.6 | Live city preview text, PostForm description textarea |
| Label | 14px (`label-md`) | 500 (600/`font-semibold` on header title only) | 1.4 | Header title ("Select Location" / "Set pickup location"), PostForm field labels, PostForm location-row primary line |
| Heading | 24px (`h3`) | 600 | 1.4 | Not used on the select-location screen itself; used only where `PostForm`'s Item Title input reuses `text-h3` (out of this phase's scope, unchanged) |
| Display | — | — | — | Not applicable — no display-scale text in this phase |

**Documented exception (inherited from Stitch, not a phase-specific decision):** `label-sm` (12px / 500 / 1.2) is used for radius preset chip labels (`{km} km`) and the FAB has no visible label (icon-only, `aria-label` only). This is the existing Stitch micro-label token, not a new size — do not introduce a 6th font size.

**Weight contract:** 2 primary weights — **400 regular** (body/description copy) and **600 semibold** (header title, Confirm button label — emphasis/CTA elements). **500 medium** appears as an inherited Stitch label-token default (radius chip text, PostForm field captions) — carry it forward unchanged, do not invent new weights.

## Color

Monochrome-first system (DESIGN.md). This phase's color usage:

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#f9f9f8` (`bg-surface` / `bg-background`) | Screen background, header bar background |
| Secondary (30%) | `#ffffff` (`surface-container-lowest`) — confirm panel, header, locate FAB, radius chip bar; `#f4f4f3` (`surface-container-low`) — inner preview row, PostForm location row background | Cards, panels, floating controls |
| Accent (10%) | `#000000` (`primary` / `on-primary` pairing) | **Reserved exclusively for:** Confirm button fill (both contexts), active radius preset chip fill, header back-button/icon pressed state. Not used for any other element on this screen. |
| Destructive | `#ba1a1a` (`error`) | **Reserved exclusively for:** geolocation permission/timeout/unavailable error text (existing `messages.post.geolocation*` keys), post-submit "location not confirmed" validation error (new, D-39) |

**Documented Stitch exception (carry forward, do not remove):** `SelectLocationRedPin` renders at `#EA4335` (classic Google Maps red) with a white center dot — this is a deliberate cartographic-landmark exception to the monochrome rule, same class as the Phase 11 emerald FREE badge exception (D-24). It is not a "UI accent" and must not be treated as a precedent for adding color elsewhere on this screen.

**Required corrections to bring current implementation in line with the Stitch monochrome/flat rules (flag for executor):**
1. Radius preset chip bar currently renders `bg-surface-container-lowest/95 ... backdrop-blur-sm` (`SelectLocationMapPane.tsx` line ~327) — **translucency + blur is glassmorphism**, explicitly forbidden by the project skill ("No gradients, glassmorphism, neon, or saturated palette drift"). Fix: solid `bg-surface-container-lowest`, no `/95` opacity, no `backdrop-blur-sm` (D-43 already specifies "Stitch light gray pills" with no mention of translucency).
2. Bottom confirm panel currently uses `rounded-xl` + `shadow-[0_4px_24px_rgba(0,0,0,0.08)]` — D-40 locks this to **`rounded-lg`, thin `border-outline-variant`, no drop shadow**. `rounded-xl` (12px) also exceeds DESIGN.md's card/modal max radius of 8px (`rounded-lg`).
3. Locate-me FAB currently has `shadow-[0_2px_8px_rgba(0,0,0,0.12)]` — D-44 specifies "light surface circle + `border-outline-variant`" with no shadow. If any shadow is kept, cap it at DESIGN.md's Level-2-overlay allowance (`0px 4px 12px rgba(0,0,0,0.05)`) — the current 0.12 opacity is too heavy. Prefer border-only, no shadow, to match D-44 literally.

## Copywriting Contract

This is a **dual-context screen** (D-01) — copy branches on `?context=post` vs. browse (default). EN is source of truth; zh/it mirror the existing `messages/{zh,it}.ts` tone (see current `selectLocation` block for reference cadence — short, imperative, no punctuation on labels).

| Element | Browse context | Post context |
|---------|-----------------|--------------|
| Screen title (`selectLocation.title` / new key) | "Select Location" (existing, unchanged) | **"Set pickup location"** (new — D-08; add trilingual keys, e.g. `selectLocation.postTitle`) |
| Primary CTA (Confirm button) | "Confirm location" (existing `selectLocation.confirm`, unchanged) | **"Confirm pickup location"** (new — D-37; e.g. `selectLocation.confirmPickup`) |
| PostForm location row — unconfirmed state | n/a | **"Tap to set pickup location"** (new — D-09; e.g. `post.locationRowPending`). Block submit until confirmed (D-39). |
| PostForm location row — confirmed state | n/a | Same city string shown in the map preview (Venice / Padova, trilingual via existing `feed.cityVenice` / `feed.cityPadova`) — no new key needed; tapping again re-opens the map with coords preloaded (D-10) |
| Live location preview row | City name only (Venice / Padova via `feed.cityVenice`/`cityPadova`) — **replaces** the static `selectLocation.selectedLocationLabel` placeholder (D-15); live-updates on pin move (D-14); `aria-live="polite"` (D-20); empty until map ready, per Loading row below | Same city-name preview pattern, same live-update/aria-live behavior |
| Loading state (map not ready) | Existing `post.mapLoading` = "Loading map…" — reuse verbatim; no preview text shown until `ready` (D-21); Confirm is enabled once ready, regardless of position | Same reused copy |
| Error — geolocation | Existing `post.geolocationDenied` / `geolocationTimeout` / `geolocationUnavailable` — reuse verbatim for the locate-me FAB failure path (see UI Considerations — currently unwired, flagged below) | Same reused copy |
| Error — post submit blocked (D-39) | n/a | **New copy needed** — no location confirmed yet. Proposed key `post.locationRequiredError`, proposed EN copy: **"Set a pickup location to continue."** — 🧪 backstop, needs explicit test per D-39 (block submit) |
| Empty state | Not applicable — this is a map picker, not a list/collection; a pin is always visible on load (saved draft → GPS → Venice default, D-03/D-27). There is no "no data" state to design copy for. | Same — not applicable |
| Destructive confirmation | None in this phase. Back-without-Confirm has explicitly no side effects (D-38) — browse center, filter prefs, and post draft are all left unchanged. There is no delete/destroy action on this screen. | Same |

**New i18n keys to add (trilingual, zh/en/it) — planner should route these into `messages/{zh,en,it}.ts`:**
- `selectLocation.postTitle` — "Set pickup location" (D-08)
- `selectLocation.confirmPickup` (or reuse under `post.*` — Claude's Discretion per CONTEXT.md; recommend keeping under `selectLocation.*` for symmetry with existing `selectLocation.confirm`) — "Confirm pickup location" (D-37)
- `post.locationRowPending` — "Tap to set pickup location" (D-09)
- `post.locationRequiredError` — "Set a pickup location to continue." (D-39, proposed — confirm exact copy with planner)

**Keys to retire (superseded, remove or leave orphaned per executor's judgment):** `post.pinCurrentLocation`, `post.pinLocationDefault`, `post.zoneLabel`, `post.pinLabel` — no longer rendered once the GPS toggle → location row swap (D-02) and zone-label hide (D-11) land.

## UI Considerations

> Populated by the ui-phase UI-consideration probe (Step 9.5) and lifted by plan-phase's
> `## UI Considerations` lift rule. Shape-rooted UI *state* coverage (empty / loading / error /
> populated / partial / overflow / zero-one-many / long-text). Empty-state and error-state COPY
> live in `## Copywriting Contract` above — this section covers state coverage and REFERENCES
> those rows rather than restating the copy.

**Elements classified for this phase:**
- Map canvas + pin (`interactive-control`, `media`)
- Live location preview row (`static-content`)
- Confirm button (`interactive-control`)
- Radius preset chip group — browse only (`interactive-control`)
- Locate-me FAB (`interactive-control`)
- Header title/back (`nav`)
- PostForm location row (`interactive-control`, `nav` — navigates to `/select-location?context=post`)
- Post submit validation (`form`)

Applicable state considerations resolved: 6 covered, 2 backstop, 2 unresolved

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| loading | Map canvas, header | ✅ covered | Map-not-ready state shows `post.mapLoading` placeholder; no preview text renders until `ready`; Confirm becomes enabled once map is ready regardless of pin position (D-21) |
| empty | Map canvas | ✅ covered | Not applicable as a true empty state — a pin is always visible on load via saved-draft → GPS → Venice-default fallback chain (D-03/D-27); there is no "zero data" map state |
| populated | Map canvas | ✅ covered | Pin + (browse-only) radius circle/radar overlay is the only "populated" state; no variable-volume content to test at scale |
| error | Locate-me FAB (browse `SelectLocationClient.handleLocateMe`) | ⚠ unresolved | Current implementation's failure callback is a silent no-op (`() => {}`, no error UI). CONTEXT.md (D-25) only says "keep locate-me FAB," doesn't specify failure UX. PostForm's own GPS toggle *does* surface `post.geolocationDenied/Timeout/Unavailable` on failure — planner should decide whether to reuse that same error copy on the map screen's FAB or intentionally keep it silent (pin retains its last valid position as a reasonable fallback either way) |
| error | Post submit (`PostForm.handleSubmit`) | 🧪 backstop | D-39 requires blocking submit when `locationConfirmed !== true`; proposed copy `post.locationRequiredError` = "Set a pickup location to continue." — needs an explicit wired test (submit attempt with unconfirmed draft → blocked + error shown) at verify time, not a silent pass |
| partial | PostForm session draft (`shoumanwu_post_draft`) | ⚠ unresolved | D-36 defines the draft shape `{ lat, lng, label, locationConfirmed }` but CONTEXT.md doesn't specify handling of a malformed/partial draft (e.g. missing `locationConfirmed`, or a stale draft from a future schema change per "Claude's Discretion: exact merge logic"). Recommend defaulting to "treat as unconfirmed" for any draft missing required fields, but this is a planner decision, not locked here |
| overflow / long-text | Preview row, header title, PostForm location row | ✅ covered | All text on this screen is short, fixed-vocabulary content — city names (Venice/Padova) and static labels/titles, never user-generated or variable-length strings. No truncation/wrap handling is needed |
| zero-one-many | — | not applicable | No list-collection element exists in this phase's UI; the map/pin is a single-position picker, not a list |
