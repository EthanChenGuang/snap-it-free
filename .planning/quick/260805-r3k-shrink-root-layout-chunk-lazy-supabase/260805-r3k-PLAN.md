# Quick Task: Shrink the root layout chunk so it stops being truncated

Homepage intermittently hangs forever on `地图加载中…` (the `next/dynamic` loading
fallback for `MapExplorer`), with the renderer pinned at 100% CPU.

## Root cause (verified)

Not the map. In a clean load the map renders correctly every time.

The dev server truncates the root layout chunk mid-transfer:

```
GET /_next/static/chunks/app/layout.js
Content-Length: 5067615
→ body closes at ~2,424,832 bytes (64 KB boundary)
curl: (18) transfer closed with 2642783 bytes remaining
```

Reproducible with plain `curl`, no browser. The browser then throws
`SyntaxError: Invalid or unexpected token` at `layout.js:809` (HTTP 200, correct
MIME — not a 404). Because this is the *root layout* chunk, React never hydrates,
so `next/dynamic` is stranded on its loading fallback permanently — no error
surface, no retry. An error boundary cannot help: hydration never starts.

Deterministic repro: touch any source file ~400 ms into a page load. Fails every
time and never recovers, even after Fast Refresh completes. Clean loads pass 8/8.

The window is wide because `app/layout.js` is **5 MB in dev** — it eagerly bundles
the whole Supabase SDK (`auth-js`, `realtime-js`, `ssr`, `postgrest`) plus Radix,
pulled in by three root-layout hooks that only touch Supabase inside effects.

Turbopack would sidestep this but is ruled out by locked decision D-13
(MapLibre/Serwist require `--webpack`).

## Approach

A plain dynamic `import()` inside those hooks does **not** split in Next dev
(measured: chunk unchanged at ~5 MB). `next/dynamic` **does** split in dev —
proven by `MapExplorer` having its own chunk. So move each Supabase-dependent
unit behind a `next/dynamic` component boundary.

## Tasks

### Task 1: Split the favorites-merge effect
- **files:** `components/providers/FavoritesMergeProvider.tsx`, `components/providers/FavoritesMergeEffect.tsx` (new)
- **action:** Provider renders `children` directly plus a `next/dynamic` headless effect component that runs `useMergeFavoritesOnLogin`
- **verify:** `@supabase` absent from the module graph reachable statically from the provider
- **done:** children render unchanged; merge still runs on login

### Task 2: Split the unread-match badge
- **files:** `components/shell/BottomNav.tsx`, `components/shell/UnreadMatchBadge.tsx` (new)
- **action:** Move `useUnreadMatchCount` into a lazily-loaded badge component; BottomNav keeps its layout/markup
- **verify:** nav renders identically with no badge until the chunk loads
- **done:** badge still appears for signed-in users with unread matches

### Task 3: Split the auth-gated iOS guide auto-open
- **files:** `components/providers/PwaOnboardingProvider.tsx`, `components/pwa/IosGuideAutoOpen.tsx` (new)
- **action:** Keep the context provider static (consumers call `usePwaOnboarding()` and it throws when absent); move only the `useAuthSession`-dependent auto-open effect behind `next/dynamic`
- **verify:** `usePwaOnboarding()` still resolves on `/settings` for `NotificationsSection` and `PushToggleSection`
- **done:** guide still auto-opens on `/settings` for signed-in iOS users

## must_haves

- `app/layout.js` no longer contains `@supabase/realtime-js` or `@supabase/auth-js`
- `app/layout.js` dev size materially below the 5,078,157-byte baseline
- Homepage still renders the map (canvas + markers) on repeated loads
- Typecheck shows no new errors in touched files
