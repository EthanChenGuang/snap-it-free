# Quick Task: Make translation retry faster (prefer OpenRouter, add timeout, no unbounded double-provider calls)

## Root cause (diagnosis completed before planning)

1. `lib/admin/translate.ts` `translateListing()` (~line 72-103) always `await`s
   `deps.openRouterGenerate()` first, and only if that returns `null`/unparseable does it
   `await deps.geminiGenerate()` — strictly sequential, never raced. A retry that fails on
   both providers pays for two full sequential LLM round-trips before giving up.
2. Neither provider call has a bound:
   - The OpenRouter `fetch()` in `translateListingWithProviders`'s `openRouterGenerate`
     (~line 137-162) and the near-duplicate in `translateListingFields`'s
     `provider === 'openrouter'` branch (~line 177-208) pass no `signal`/`AbortSignal` at
     all — a hung OpenRouter call blocks indefinitely.
   - The Gemini call via `@google/genai`'s `ai.models.generateContent(...)`
     (~line 124-131) also has no per-call timeout configured.
3. `app/api/admin/translation/retry/route.ts` calls
   `translateListingFields(input, 'gemini', options)` — the `'gemini'` provider argument
   is a misleading name (per code comment "Alias used by ingest hook and retry API
   (D-24)") but it does NOT skip OpenRouter: it delegates to
   `translateListingWithProviders`, which is OpenRouter-primary / Gemini-fallback. This
   is the correct/desired behavior per the user's cost preference and is **not** changed
   by this task — only the underlying provider calls get bounded.

**Hard constraint (user-locked):** OpenRouter stays the first-tried, primary provider in
every code path touched below. No parallel/racing calls are introduced (racing would let
Gemini win even when OpenRouter would have succeeded, defeating the cost preference).
Speed comes from bounding each provider's worst-case latency, not from reordering or
racing providers.

Verified via Context7 (`/googleapis/js-genai`): `ai.models.generateContent(...)` accepts
`config.httpOptions.timeout` (milliseconds, client-side request timeout) and
`config.abortSignal`; a client-side timeout throws `APIConnectionTimeoutError`, already
caught by the existing bare `catch { return null; }` in the Gemini call.

## Tasks

### Task 1: Add bounded timeouts to both providers and dedupe the OpenRouter fetch logic
- **files:** `lib/admin/translate.ts`
- **action:** Add two exported constants near `MAX_INPUT_CHARS`:
  `export const OPENROUTER_TIMEOUT_MS = 8000;` and
  `export const GEMINI_TIMEOUT_MS = 8000;`.
  Extract a single private helper `callOpenRouterProvider(prompt: string, options: { openRouterApiKey?: string; openRouterModel?: string; fetchFn?: typeof fetch }): Promise<string | null>`
  containing the fetch-and-parse body currently duplicated in
  `translateListingWithProviders`'s `openRouterGenerate` and in
  `translateListingFields`'s `provider === 'openrouter'` branch. Inside this helper, add
  `signal: AbortSignal.timeout(OPENROUTER_TIMEOUT_MS)` to the `fetchFn(...)` call's
  options object (alongside `method`, `headers`, `body`) so a hung/slow OpenRouter
  response aborts after `OPENROUTER_TIMEOUT_MS` instead of blocking indefinitely; keep
  the existing `try { ... } catch { return null; }` wrapper so an abort is treated the
  same as any other provider failure.
  Extract a second private helper `callGeminiProvider(prompt: string, options: { geminiApiKey?: string }): Promise<string | null>`
  containing the body currently inlined in `translateListingWithProviders`'s
  `geminiGenerate`. Inside this helper, add `httpOptions: { timeout: GEMINI_TIMEOUT_MS }`
  to the `config` object passed to `ai.models.generateContent(...)`, alongside the
  existing `systemInstruction` and `temperature` keys, so a hung Gemini fallback call is
  also bounded.
  Update `translateListingWithProviders` to call `callGeminiProvider(prompt, options)`
  and `callOpenRouterProvider(prompt, options)` from its `deps` object instead of
  inlining the logic. Update `translateListingFields`'s `provider === 'openrouter'`
  branch to call `callOpenRouterProvider(prompt, options)` instead of its duplicated
  fetch block, keeping `geminiGenerate: async () => null` for that branch unchanged
  (openrouter-only mode intentionally still skips Gemini entirely).
  Do NOT change the call order inside `translateListing` (OpenRouter awaited first,
  Gemini awaited only on OpenRouter failure) — that is the user-locked "prefer OpenRouter
  for cost" behavior. Do NOT change
  `app/api/admin/translation/retry/route.ts`'s existing
  `translateListingFields(input, 'gemini', options)` call site — it already routes
  through the now-bounded `translateListingWithProviders`.
- **verify:**

  (type-checks the refactor)
  <automated>grep -c "AbortSignal.timeout(OPENROUTER_TIMEOUT_MS)" lib/admin/translate.ts</automated>
  (expect `1` — single source of truth, no duplicate fetch block left)
  <automated>grep -c "httpOptions: { timeout: GEMINI_TIMEOUT_MS }" lib/admin/translate.ts</automated>
  (expect `1`)
- **done:** `callOpenRouterProvider` and `callGeminiProvider` are the single source of
  truth for each provider call; both `translateListingWithProviders` and
  `translateListingFields` use them instead of inline/duplicated logic; every OpenRouter
  fetch passes `AbortSignal.timeout(OPENROUTER_TIMEOUT_MS)`; every Gemini call passes
  `httpOptions: { timeout: GEMINI_TIMEOUT_MS }`; `translateListing`'s
  OpenRouter-then-Gemini order is byte-for-byte unchanged; `npm run lint` passes clean.

## must_haves

- **truths:** A translation retry that fails on OpenRouter is bounded by a hard
  client-side timeout instead of hanging indefinitely, and still falls back to Gemini
  before the request gives up. OpenRouter remains the first-tried, preferred (cheaper)
  provider in every call path — no behavior change to provider order, no racing.
- **artifacts:** `lib/admin/translate.ts` exports `OPENROUTER_TIMEOUT_MS` and
  `GEMINI_TIMEOUT_MS`, and has single-source `callOpenRouterProvider`/
  `callGeminiProvider` helpers used by both `translateListingWithProviders` and
  `translateListingFields`. `lib/admin/translate.test.ts` covers the timeout wiring with
  2 new tests alongside the 3 existing ones.
- **key_links:** `app/api/admin/translation/retry/route.ts` →
  `translateListingFields(input, 'gemini', options)` → `translateListingWithProviders` →
  `callOpenRouterProvider` (bounded, primary, tried first) → `callGeminiProvider`
  (bounded, fallback, tried only on OpenRouter failure).
