# Quick Task: Research Italian and European free-item source candidates beyond Subito

Subito.it is currently the only configured and implemented scraping source. This task
researches which other Italian and European sites are viable candidates for free-item
supply, and produces a decision-ready shortlist.

**Scope correction from the user:** coverage is evaluated **Italy-wide**, not Venice-only.
Venice/Veneto strength is still recorded (it is the launch market), but a candidate that
only works in Venice is worth less than one with national reach.

This is a **research task** — the deliverable is a document, not code. No scrapers are
implemented here.

## Why this matters now

`.planning/STATE.md` carries an open blocker against the one source that exists:

> Phase 1: Subito.it's `robots.txt` explicitly forbids scraping (not a soft crawl-delay) —
> needs a documented ToS/legal review before pointing at production, and a non-scraping
> fallback supply plan

So this research serves two purposes at once: widening supply, and identifying a
**non-scraping fallback** (official API, RSS, feed, partnership, or open data) that does not
inherit Subito's legal exposure.

## What the existing implementation constrains

Any new source has to land in the shape the shared pipeline already expects.

`scraper/src/subito/extract.ts:6-15` defines the contract every source must satisfy:

```ts
export type RawListing = {
  external_id: string;
  title: string;
  photo_url: string;
  external_url: string;
  lat: number | null;
  lng: number | null;
  posted_at: string;
  description?: string;
};
```

Per-source code is a thin triple — `categories.ts` (URL/seed building), `extract.ts`
(selectors → `RawListing`), `crawler.ts` (Crawlee `PlaywrightCrawler` + optional proxy) —
feeding shared `normalize` / `free-filter` / `dedupe` / `zone-tag` / `persist` stages
(`scraper/src/shared/`). A new source is therefore cheap **if** it yields those eight fields.

Two hard blockers for Italy-wide scope, both currently Venice-hardcoded:

1. `scraper/src/subito/extract.ts:28-31` rejects any coordinate outside a Venice bounding box
   (`lat 45.0–45.7, lng 12.1–12.6`). Italy-wide listings would be silently dropped to `null`.
2. `scraper/src/geo/municipality-centroids.json` holds **7 entries, all Venice-area**
   (Venezia, Venice, Mestre, Marghera, Lido, …). The centroid fallback cannot resolve any
   other Italian comune.

`photo_url` being **required** (`extract.ts:209` returns `null` without it) is a real filter:
text-only sources (mailing lists, Telegram, bulletin boards) fail the contract as written.
The research must flag which candidates can't supply a photo.

## Research questions

Per candidate, the shortlist must answer:

1. **Coverage** — Italy-wide, regional, or single-city? Which cities are strongest? Evidence
   of actual free-item volume, not just that a "free" filter exists.
2. **Free-item structure** — is there a real `regalo`/`gratis`/`gratuito` category or a
   price=0 filter, and what are the URL patterns?
3. **Access route** — official API, RSS, sitemap, JSON-LD/structured data, or DOM scraping
   only? A documented API outranks scraping decisively.
4. **Legal posture** — `robots.txt` stance, ToS scraping clauses, and whether an official
   route sidesteps both. Note EU/Italian framing (sui generis database right, DSM TDM
   exceptions, GDPR on listing personal data).
5. **Anti-bot difficulty** — login wall, fingerprinting, rate limits, Cloudflare, CAPTCHA;
   and the proxy cost implied against the **$20–100/month total** budget.
6. **Schema fit** — can it yield all eight `RawListing` fields, especially `photo_url`,
   `posted_at`, and geo precision (exact coords vs city-level only)?
7. **Duplication** — does its inventory largely mirror Subito/Facebook, or is it additive?
