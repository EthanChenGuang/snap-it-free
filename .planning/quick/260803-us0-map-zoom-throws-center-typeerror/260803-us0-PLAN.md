# Quick Task: Map zoom throws "reading 'center'" TypeError

Zooming the map throws two runtime errors in sequence:

1. `TypeError: Cannot read properties of undefined (reading 'center')`
2. `Error: Attempting to run(), but is already running.`

## Diagnosis (completed before planning)

Error 1 is thrown from `@vis.gl/react-maplibre` 8.1.1:

```
at transformToViewState (@vis.gl/react-maplibre/dist/utils/transform.js:9)
at Maplibre._onCameraEvent (@vis.gl/react-maplibre/dist/maplibre/maplibre.js:107)
at fire -> _fireEvent -> _fireEvents -> _updateMapTransform -> _applyChanges
at TaskQueue.run -> Map._render
```

Line 107 is `transformToViewState(this._map.transform)`. Verified on the live
MapLibre 6.0.0 instance: `typeof map.transform === 'undefined'`, no own property, no
prototype descriptor — while `map.getCenter()` returns `[12.33, 45.44]` normally. MapLibre 6
removed the public `transform` property; the wrapper reads it in three places
(lines 107, 311, 326), so camera events and resize all break.

`@vis.gl/react-maplibre` declares `maplibre-gl: >=4.0.0`, an open-ended range predating v6,
so npm installed 6.0.0 without a peer warning.

Error 2 is fallout, not a separate bug. `TaskQueue.run()` has no `try/finally`:

```ts
const queue = this._currentlyRunning = this._queue;
for (const task of queue) { task.callback(timeStamp); }   // throws here
this._currentlyRunning = false;                            // never reached
```

Once a task callback throws, `_currentlyRunning` stays set and every later frame throws
"already running". Fixing error 1 fixes error 2.

`@vis.gl/react-maplibre` 8.1.2 fixes this upstream: `transformToViewState(map.transform)` is
replaced by `getTransformLike(map)`, built from public getters (`getCenter`, `getZoom`,
`getBearing`, `getPitch`, `getPadding`). No `map.transform` access remains.
`react-map-gl@8.1.2` pins `@vis.gl/react-maplibre@8.1.2`.
