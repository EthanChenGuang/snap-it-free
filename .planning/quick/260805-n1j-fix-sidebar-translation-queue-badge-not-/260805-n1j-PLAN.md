# Quick Task: Sidebar translation queue badge not refreshing after retry

On `/admin/translation`, clicking "重试" (retry) on a single failed listing succeeds and
the header banner count ("翻译队列: N 条 listing 等待翻译") updates immediately. The badge
next to "翻译队列" in the left sidebar nav (rendered by `AdminShell`) stays stale until a
full page reload/navigation.

## Root cause (diagnosis completed before planning)

The two counts are **not** the same data source and there is no shared query cache
(no React Query/SWR in this codebase) — this is plain Next.js App Router Server/Client
Component split:

1. `app/admin/layout.tsx` (Server Component) calls `getPendingTranslationCount()`
   (`lib/admin/queries.ts:239`) once per layout render and passes the result as the
   `pendingTranslationsCount` prop into `components/admin/AdminShell.tsx`. `AdminShell`
   renders **both** the sidebar nav badge (`badgeCount('pendingTranslations', ...)`,
   line ~68) and the top-bar pill (line ~121) from this single server-fetched prop.

2. `app/admin/translation/page.tsx` (Server Component) calls `getTranslationQueue()`
   once and passes `initialItems` into `components/admin/TranslationQueueClient.tsx`
   (Client Component), which copies it into local `useState(initialItems)`. Its own
   on-page banner reads `pendingCount = items.length` — local client state, not the
   server prop.

3. `TranslationQueueClient.handleRetry` / `handleBulkRetry` call
   `POST /api/admin/translation/retry`, then `refreshFromResponse(result.processed)`
   filters the retried listing(s) out of local `items` state. This is why the
   **on-page** banner updates instantly — it's reading local state, not a shared cache.

4. Nothing in `TranslationQueueClient.tsx` ever calls `router.refresh()`. In the Next.js
   App Router, a client-side `fetch()` mutation never re-runs Server Component data
   fetching (i.e. `AdminLayout`'s `getPendingTranslationCount()` call) on its own —
   that only happens on a real navigation or an explicit `router.refresh()`. So
   `AdminShell`'s `pendingTranslationsCount` prop — and therefore the sidebar badge and
   the top-bar pill — stays frozen at whatever it was when the layout last rendered.

5. This exact "mutate via fetch, then `router.refresh()` to re-sync Server Component
   props" pattern is already established elsewhere in this codebase:
   `components/admin/DashboardClient.tsx` (lines 60, 81, 100),
   `components/admin/SourceDetailClient.tsx` (line 96), and
   `components/admin/SettingsClient.tsx` (lines 62, 107, 133, 161) all call
   `router.refresh()` from `useRouter()` (`next/navigation`) right after a successful
   mutation. `TranslationQueueClient.tsx` is the one admin client component missing
   this call.

## Tasks

### Task 1: Call `router.refresh()` after successful retry
- **files:** `components/admin/TranslationQueueClient.tsx`
- **action:** Import `useRouter` from `next/navigation` and call `const router = useRouter()`
  at the top of the component, matching the existing pattern in `DashboardClient.tsx`. In
  `handleRetry`, call `router.refresh()` immediately after `refreshFromResponse(result.processed)`
  succeeds (inside the `try` block, after the existing state update, before the `finally`).
  Do the same in `handleBulkRetry` after its `refreshFromResponse(result.processed)` call.
  Do **not** call `router.refresh()` inside the `catch` blocks — only on success, so a failed
  retry doesn't wipe the error message via a layout re-render. This makes `AdminShell` re-fetch
  `pendingTranslationsCount` (and `rejectsCount`/`footerStats`) via the Server Component layout
  tree while `TranslationQueueClient`'s own local `items` state (and its on-page banner) keeps
  working exactly as before.
- **verify:**
  <automated>npm run lint</automated>
  (type-checks the new `useRouter` import/usage; `tsc --noEmit` per `package.json` `lint` script)
- **done:** `TranslationQueueClient.tsx` imports `useRouter`, holds a `router` instance, and
  calls `router.refresh()` in both `handleRetry` and `handleBulkRetry` success paths only.

### Task 2: Verify the sidebar badge refreshes end-to-end

## must_haves

- **truths:** After a successful single-item retry on `/admin/translation`, the sidebar
  "翻译队列" nav badge decrements in the same render pass as the on-page header banner —
  no full reload/navigation required. A failed retry leaves the sidebar badge and the error
  message untouched (no spurious refresh wipes the error banner).
- **artifacts:** `components/admin/TranslationQueueClient.tsx` imports `useRouter` from
  `next/navigation` and calls `router.refresh()` after both `handleRetry` and
  `handleBulkRetry` succeed.
- **key_links:** `components/admin/TranslationQueueClient.tsx` (client mutation) →
  `router.refresh()` → `app/admin/layout.tsx` (`getPendingTranslationCount()`) →
  `components/admin/AdminShell.tsx` (`pendingTranslationsCount` prop → sidebar badge +
  top-bar pill).
