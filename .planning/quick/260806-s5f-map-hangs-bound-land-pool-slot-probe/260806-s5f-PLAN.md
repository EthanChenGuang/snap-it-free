# Quick Task 260806-s5f: Map hangs — bound the land-pool slot probe

## Symptom

`/` renders the shell (header, bottom nav) and the map's `next/dynamic` fallback
`地图加载中…`, then never progresses. The Chrome renderer pins one core at ~99%
indefinitely; Playwright cannot even take an accessibility snapshot (30s timeout).

## Not the previous cause

Two earlier quick tasks (`260805-r3k`, `260805-ws8`) fixed a *dev-server chunk
truncation* with the same user-visible symptom. That is **not** what is happening now:

- `app/layout.js` is 1,362,707 bytes — still 734 KB under the 2 MiB cliff ws8 cleared.
- Parallel-fetch repro across all 6 chunks the page pulls: no truncation, 3/3 rounds.
  Responses are chunked (no `Content-Length`), and every body matches its on-disk size.
- Browser console shows `[HMR] connected` and no `SyntaxError`. Hydration *starts*.

## Root cause

`landCoordForListing` in `lib/map/venice-land-coords.ts` linear-probes for a free
slot in a fixed-size coordinate pool with **no bound**:

```ts
let slot = stableSlot(listing.id, pool.length);
while (reservedSlots.has(slot)) {
  slot = (slot + 1) % pool.length;   // never terminates once every slot is reserved
}
```

`resolveGroupPins` (`lib/map/map-pin-layout.ts:20`) shares one `reservedSlots` Set
across every listing in a coordinate group. Once the group has more listings than
the pool has slots, every slot is reserved and the `while` spins forever.

Pool sizes: `CENTRO_STORICO_LAND` 48, `MESTRE_MARGHERA_LAND` 10, `LIDO_MURANO_LAND` 8.

**action:** Add tests that a group larger than its pool resolves in bounded time:
one for `resolveGroupPins` with 102 zone-`null` listings (Padova shape) and one for

**verify:** `npx vitest run lib/map/map-pin-layout.test.ts` — new tests time out / hang before the fix.

**done:** Tests exist and fail (hang) against current `venice-land-coords.ts`.

### Task 2 — bound the probe

**files:** `lib/map/venice-land-coords.ts`

**action:** In `landCoordForListing`, when `reservedSlots.size >= pool.length` the
pool is exhausted — clear the set to begin a fresh round before probing. This makes
the `while` provably terminate (on entry `size < pool.length`, so a free slot
exists) and spreads overflow listings evenly across the pool instead of piling them
onto one coordinate. The size check reads the *current* pool's length, so it is also
correct when a group mixes zones with different pool sizes.

**verify:** `npx vitest run lib/map/` — all green, including the new tests.

**done:** No unbounded loop remains; existing uniqueness tests still pass.

**verify:** Accessibility snapshot returns; renderer CPU drops to idle.

**done:** Map renders with pins.
