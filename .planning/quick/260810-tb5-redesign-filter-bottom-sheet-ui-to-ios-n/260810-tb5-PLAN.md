<recon_findings>
Read during planning — treat as established fact, do not re-derive.

1. **The drag-handle pill already exists.** `components/ui/drawer.tsx` `DrawerContent` renders `DrawerPrimitive.Handle` containing `<span class="h-1 w-12 rounded-full bg-gray-300 ... dark:bg-zinc-600" />` inside a `py-3` wrapper. Per the scope constraint: **reuse it, do NOT add a second pill in FilterSheet.** The spec asks for `w-9` (36px) vs the existing `w-12` (48px); changing `drawer.tsx` would restyle the map sheet and select-location sheet too, which is out of scope. **Accepted deviation: pill stays 48px wide.**

2. **`Button` (components/ui/button.tsx) fights this spec.** Its base class bakes in `rounded` (4px) and `text-label-md`; `size="sm"` bakes in `h-8`, `size="default"` bakes in `h-9`. A fixed `h-*` and the spec's `py-2` / `py-2.5` / `py-3.5` are different CSS properties, so `tailwind-merge` will NOT resolve the conflict — the height would silently win. **Therefore every chip and both action buttons in this plan are plain `<button type="button">`, not `<Button>`.** That means the focus ring must be added by hand.

3. **`cn()` uses an extended `tailwind-merge`** (`lib/utils.ts`) that knows the custom `text-h3` / `text-label-md` scale, so passing `text-xl` via `className` to `DrawerTitle` correctly overrides its default `text-h3`.

4. **18 categories, with long Italian labels** (e.g. "Arredamento e Casalinghi", "Console e Videogiochi") from `lib/admin/subito-regalo-catalog.ts`. In a 3-column grid on a 375px viewport each chip is roughly 100px wide, so labels WILL wrap to 2-3 lines. The chip style must handle wrapping deterministically (`leading-tight`, `break-words`, flex-centered content, equal row heights).

5. **All required i18n keys already exist** in `messages/en.ts` (`feed.filtersTitle`, `feed.cityFilterMapHint`, `feed.cityLabel`, `feed.categoriesLabel`, `feed.clearSelection`, `feed.resetFilters`, `feed.applyFilters`, `feed.cityAll` / `cityVenice` / `cityPadova`). **No new message keys are needed; `messages/*.ts` must not be edited by this plan.**

6. **Dirty working tree (pre-existing, unrelated to this plan):** `components/listings/FilterSheet.tsx`, `components/ui/drawer.tsx`, `messages/en.ts`, `messages/it.ts`, `messages/zh.ts` are all already modified, and `messages/subito-category-labels.ts` is untracked. The executor's commits must `git add` **only** `components/listings/FilterSheet.tsx` — that one commit will unavoidably sweep in the pre-existing uncommitted FilterSheet edits, which is expected. Do not stage `drawer.tsx` or `messages/*`.

7. **`human_verify_mode` is `end-of-phase`**, so this plan carries no `checkpoint:human-verify` task; the visual confirmation lives in `<verify><human-check>` on Task 3.
</recon_findings>
