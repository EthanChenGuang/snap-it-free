# Quick Task 261026-3w6: structured Stripe route errors, signed-in locked card

Two bug fixes on PR #8. No Stripe, Vercel or database access.

## Facts that shape the design

- `POST /api/stripe/checkout` and `POST /api/stripe/portal` have no try/catch. A Stripe error such as "No such price" escapes, so Next answers an empty 500 and the only log line is Next's own dump of the error object.
- `GET /api/stripe/checkout/return` catches Stripe errors, but `requireAuth()` sits outside its try, so an auth failure is still an empty 500 on the success_url. The webhook already catches and returns 500 so that Stripe retries. It stays as it is.
- The client already maps any non-2xx checkout response to `purchase = 'error'` (`checkoutOutcome`). Settings already shows `portalError`. That copy exists in en/it/zh, but no test proves either one renders.
- "Already subscribed? Sign in" lives in `LockedCard` (`components/onboarding/LockedViews.tsx`), which every locked view shares: home, detail and favorites. The paywall itself shows a "Restore purchases" link, not a sign-in prompt.
- `useAuthSession()` is the client's existing source of auth state (BottomNav, the detail shells).

## Decisions

- Shared `lib/stripe/route-errors.ts` with `stripeRouteError(tag, error)`.
  - A Stripe SDK error (`instanceof Stripe.errors.StripeError`) gives 502 `{ error: 'stripe_error' }`. Anything else gives 500 `{ error: 'internal_error' }`.
  - It logs one `console.error('[stripe] <tag> failed', { type, code, message })`. The message has `sk_/rk_/pk_/whsec_` tokens redacted. It never logs the error object, the request or the headers.
- Existing contracts are unchanged: 503 payments_disabled, 401, 400, 404, 409, and 502 checkout_unavailable. The return route still always redirects (to pending on failure).
- Signed-in locked card: it replaces "Sign in" with **"Refresh status"**, a button that runs the existing `checkRestore()`.
  - If the user is entitled, it reloads into the open feed. If not, it shows a localized status line.
  - This fits the existing "activation can take a minute" note after Checkout better than hiding the line.
  - Signed-out users keep the Sign in link. While auth is still loading, the line is not rendered, so a signed-in user never flashes the sign-in prompt.
- Paywall and Settings errors get stable test ids (`paywall-checkout-error`, `settings-portal-error`). Copy is unchanged apart from the new locked strings.
